## Evidence labels

- **Implemented locally:** code and tests exist in the current `main` tree; this does not mean the production deployment contains them.
- **Partial:** some real behavior exists, but the specified end-to-end capability is incomplete.
- **Historical candidate:** code is available on another retained Git ref, not current `main`.
- **Production source recovered / not active main:** the production revision is available on a retained ref, but has not been reconciled into the current `main` checkout.
- **Production observed / source missing:** behavior or configuration was observed live, but its authoritative source was not recovered.
- **Specified only:** the requirement appears in the vision/specification but no corresponding working implementation was found.

## Evidence and provenance categories

The current customer experience and record model distinguish these kinds of information:

1. **Measured:** relative microphone FFT values, peak bins, RMS, sample rate/FFT resolution, and capture window. These describe the instrument output, not a source or meaning.
2. **Generated:** the DTMF-like tone packet and local speaker playback. The app records it as generated/local output, not received data.
3. **Decoded:** text reconstructed from the in-memory symbol packet with header/length/CRC checks. No acoustic receiver has yet reconstructed a message from an independent recording.
4. **AI interpretation:** schema-validated model output from the supplied measurement summary; currently unavailable at runtime due to quota.
5. **Spiritual/personal interpretation:** optional AI faith reflection or user-entered personal reflection, kept separate from measured values and scientific interpretation.
6. **Experimental conclusion:** not yet established for external communication. Follow-up microphone observations and correlation do not by themselves prove intent, identity, or causation.
